
Oke, sekarang kita udah tahu kenapa git itu berguna. Tapi ada satu masalah lagi. Kalau project kita cuma disimpan di laptop, terus laptopnya tiba-tiba rusak, hilang, atau dipinjam kucing kamu buat main game, gimana? Ya, project-nya bisa ikut hilang juga. Nah, makanya kita bisa simpan repository kita secara online menggunakan **GitHub**.

Bentar, git sama GitHub itu beda? Yup. **Git** adalah *version control system* yang kita pakai buat mengelola perubahan project, sedangkan **GitHub** adalah platform buat menyimpan dan berkolaborasi dalam repository git secara online. Jadi, kamu bisa pakai git tanpa GitHub, tapi di tutorial ini kita bakal pakai keduanya.

Sebelum kita bisa kirim perubahan dari laptop ke GitHub menggunakan `git push`, kita perlu mengatur cara laptop kita berkomunikasi dengan GitHub. Salah satu caranya adalah menggunakan **SSH (Secure Shell)**. Dengan SSH, GitHub bisa mengenali laptop kita lewat sepasang *key*, jadi kita gak perlu login pakai username dan password GitHub setiap kali melakukan operasi git.

Bayangin aja SSH key ini kayak kunci dan gembok. Ada **public key** yang boleh kita kasih ke GitHub, dan ada **private key** yang harus tetap disimpan di laptop kita. Jadi, jangan sampai private key kamu dikirim ke teman atau di-upload ke repository, ya. Nanti yang punya akses ke repository kamu malah bukan cuma kamu.

Tutorialnya aku pisah jadi dua versi. Pilih sesuai sistem operasi dan terminal yang kamu pakai:

- **Windows:** menggunakan **PowerShell**, bukan Command Prompt atau Git Bash.
- **Linux:** menggunakan **Bash**.

Sebelum mulai, pastikan kamu sudah punya akun [GitHub](https://github.com/) dan sudah meng-install Git serta OpenSSH. Kita juga bakal pakai algoritma **Ed25519** buat membuat SSH key.

### Versi 1: Windows (PowerShell)

#### 1. Pastikan Git dan SSH sudah terpasang

Pertama, buka **PowerShell**. Bisa lewat Start Menu, Windows Terminal, atau terminal di VS Code. Terus coba jalankan:

```powershell
git --version
ssh -V
```

Kalau muncul nomor versinya, berarti Git dan SSH sudah bisa dipakai. Kalau `git` gak dikenali, install dulu [Git for Windows](https://git-scm.com/downloads/win). Kalau `ssh` gak dikenali, pastikan fitur **OpenSSH Client** di Windows sudah terpasang.

#### 2. Cek apakah kamu sudah punya SSH key

Sebelum bikin kunci baru, kita cek dulu apakah sebelumnya kamu sudah punya SSH key. Ketik:

```powershell
Get-ChildItem "$HOME\.ssh"
```

Kalau folder `.ssh` belum ada dan muncul error, tenang, itu normal kalau kamu belum pernah bikin SSH key. Kalau ada file seperti `id_ed25519` dan `id_ed25519.pub`, berarti kamu sudah punya sepasang SSH key. Kamu boleh pakai key itu kalau memang ingin menggunakannya untuk GitHub.

#### 3. Buat SSH key baru

Kalau belum punya key, jalankan:

```powershell
ssh-keygen -t ed25519 -C "email_kamu@example.com"
```

Ganti `email_kamu@example.com` dengan email yang kamu pakai di GitHub. Bagian `-t ed25519` berarti kita mau membuat key dengan algoritma Ed25519, sedangkan `-C` dipakai untuk memberi label pada key tersebut.

Nanti kamu akan ditanya di mana key-nya mau disimpan. Kalau belum punya key dengan nama yang sama, cukup tekan **Enter** untuk memakai lokasi default. Biasanya file-nya bakal disimpan di `C:\Users\USERNAME\.ssh\`.

Terus kamu akan ditanya mau memakai **passphrase** atau enggak. Passphrase ini semacam password tambahan untuk melindungi private key kamu. Sebaiknya isi dengan passphrase yang kuat, lalu konfirmasi. Saat diketik, karakternya memang gak kelihatan. Itu normal.

**Penting:** Kalau muncul pertanyaan untuk menimpa (*overwrite*) key yang sudah ada, jangan asal pilih `yes`. Kamu bisa memakai key lama atau membuat key baru dengan nama file berbeda. Jangan sampai key yang masih dipakai malah hilang.

Setelah selesai, kamu bakal punya dua file:

- `id_ed25519` -> **private key**. Jangan dibagikan.
- `id_ed25519.pub` -> **public key**. Ini yang nanti kita masukkan ke GitHub.

#### 4. Jalankan ssh-agent

Kita bakal memakai `ssh-agent` buat membantu mengelola SSH key dan passphrase tadi. Buka **PowerShell sebagai Administrator**, lalu jalankan:

```powershell
Get-Service -Name ssh-agent | Set-Service -StartupType Manual
Start-Service ssh-agent
```

Setelah itu, buka PowerShell biasa (gak perlu Administrator lagi), lalu masukkan private key ke `ssh-agent`:

```powershell
ssh-add "$HOME\.ssh\id_ed25519"
```

Kalau kamu tadi membuat key dengan nama lain, sesuaikan nama file-nya. Jika diminta, masukkan passphrase yang tadi kamu buat. Kamu bisa cek key yang sudah dimuat menggunakan:

```powershell
ssh-add -l
```

#### 5. Tambahkan public key ke GitHub

Sekarang waktunya ngasih public key kita ke GitHub. Biar gak capek ngeblok teks yang panjang banget, kita bisa langsung menyalinnya ke clipboard:

```powershell
Get-Content "$HOME\.ssh\id_ed25519.pub" | Set-Clipboard
```

Lalu buka [GitHub SSH Keys](https://github.com/settings/keys), atau masuk ke **Profile > Settings > SSH and GPG keys**. Klik **New SSH key**, lalu:

1. Isi **Title**, misalnya `Laptop Windows`.
2. Pilih **Key type: Authentication Key**.
3. Paste public key tadi ke kolom **Key**.
4. Klik **Add SSH key**.

Nah, sekarang GitHub sudah punya public key laptop kamu. Ingat, yang dimasukkan ke GitHub itu file yang berakhiran `.pub`, ya. Jangan kebalik.

#### 6. Tes koneksi SSH ke GitHub

Balik lagi ke PowerShell, lalu ketik:

```powershell
ssh -T git@github.com
```

Saat pertama kali terhubung, SSH mungkin akan bertanya apakah kamu percaya dengan server GitHub. **Cek fingerprint yang ditampilkan** dan cocokkan dengan [fingerprint resmi GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/githubs-ssh-key-fingerprints). Kalau cocok, ketik `yes`.

Kalau berhasil, kurang lebih muncul tulisan:

```text
Hi USERNAME! You've successfully authenticated, but GitHub does not provide shell access.
```

Tenang, tulisan `does not provide shell access` itu normal, bukan error. Justru itu tandanya GitHub sudah berhasil mengenali kamu. Yeay!

**Catatan khusus Windows:** Kalau nanti `git push` masih minta passphrase berkali-kali padahal key sudah masuk ke `ssh-agent`, bisa jadi Git for Windows memakai program SSH yang berbeda. Kamu bisa mengarahkan Git supaya memakai OpenSSH bawaan Windows:

```powershell
git config --global core.sshCommand "C:/Windows/System32/OpenSSH/ssh.exe"
```

### Versi 2: Linux (Bash)

Oke, sekarang buat yang pakai Linux. Konsepnya sama aja dengan Windows, cuma perintah untuk mengelola file dan `ssh-agent` sedikit berbeda. **Semua perintah di bawah ini untuk Bash**, jadi pastikan kamu menjalankannya di terminal Bash.

#### 1. Pastikan Git dan SSH sudah terpasang

Buka terminal, lalu jalankan:

```bash
git --version
ssh -V
```

Kalau muncul informasi versinya, berarti aman. Kalau salah satunya belum terpasang, install paket `git` dan `openssh-client` (atau nama paket OpenSSH yang sesuai dengan distribusi Linux kamu) melalui *package manager* masing-masing.

#### 2. Cek SSH key yang sudah ada

Sekarang kita cek folder `.ssh`:

```bash
ls -al ~/.ssh
```

Kalau muncul `No such file or directory`, berarti folder-nya belum ada. Gak masalah. Kalau kamu menemukan `id_ed25519` dan `id_ed25519.pub`, berarti sudah ada SSH key dan kamu bisa memutuskan mau memakainya atau membuat key lain.

#### 3. Buat SSH key baru

Kalau belum punya, jalankan:

```bash
ssh-keygen -t ed25519 -C "email_kamu@example.com"
```

Sama seperti Windows, ganti email contohnya dengan email kamu di GitHub. Setelah itu, tekan **Enter** untuk menyimpan key di lokasi default (biasanya `~/.ssh/id_ed25519`) kalau nama file tersebut belum dipakai.

Kamu juga akan diminta membuat **passphrase**. Sebaiknya isi passphrase untuk keamanan tambahan. Terus, ingat dua file ini:

- `~/.ssh/id_ed25519` -> **private key**. Simpan baik-baik.
- `~/.ssh/id_ed25519.pub` -> **public key**. Ini yang boleh dikasih ke GitHub.

Kalau nama file default sudah ada, **jangan overwrite key lama**. Pakai key yang sudah ada atau buat key baru dengan nama yang berbeda.

#### 4. Jalankan ssh-agent

Sekarang kita jalankan `ssh-agent` di terminal Bash:

```bash
eval "$(ssh-agent -s)"
```

Kalau berhasil, biasanya muncul tulisan seperti `Agent pid 12345`. Angkanya bisa beda-beda, jadi gak perlu disamain. Lalu tambahkan private key:

```bash
ssh-add ~/.ssh/id_ed25519
```

Kalau diminta passphrase, masukkan passphrase yang tadi dibuat. Untuk cek apakah key sudah masuk, jalankan:

```bash
ssh-add -l
```

Perlu diingat, perintah `eval` di atas menjalankan atau menghubungkan agent untuk sesi shell saat ini. Di beberapa lingkungan Linux, agent sudah berjalan otomatis; di lingkungan lain kamu mungkin perlu mengaturnya lagi saat membuka sesi baru.

#### 5. Tambahkan public key ke GitHub

Sekarang kita tampilkan public key yang tadi dibuat:

```bash
cat ~/.ssh/id_ed25519.pub
```

Copy **seluruh output** yang muncul, mulai dari `ssh-ed25519` sampai bagian akhirnya. Setelah itu, buka [GitHub SSH Keys](https://github.com/settings/keys), klik **New SSH key**, lalu:

1. Isi **Title**, misalnya `Laptop Linux`.
2. Pilih **Key type: Authentication Key**.
3. Paste public key tadi ke kolom **Key**.
4. Klik **Add SSH key**.

Yup, bagian ini sama persis dengan Windows. Yang penting jangan sampai kamu malah meng-copy private key. File tanpa ekstensi `.pub` itu jangan dibagikan ke siapa-siapa.

#### 6. Tes koneksi SSH ke GitHub

Terakhir, jalankan:

```bash
ssh -T git@github.com
```

Kalau baru pertama kali menghubungkan laptop ke GitHub, kamu mungkin diminta memastikan fingerprint server. Cocokkan dulu dengan [fingerprint resmi GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/githubs-ssh-key-fingerprints). Kalau cocok, jawab `yes`.

Kalau berhasil, output-nya kurang lebih seperti ini:

```text
Hi USERNAME! You've successfully authenticated, but GitHub does not provide shell access.
```

Dan... selesai! Laptop Linux kamu sekarang sudah bisa terhubung ke GitHub menggunakan SSH.

### Terus, SSH-nya dipakai buat apa?

Nah, setelah koneksinya berhasil, sekarang kamu bisa memakai **SSH URL** saat mengambil repository dari GitHub. Misalnya kamu punya repository bernama `MyProject`, kamu bisa menjalankan perintah ini di **PowerShell maupun Bash**:

```bash
git clone git@github.com:USERNAME/MyProject.git
```

Ganti `USERNAME` dengan username GitHub kamu, dan `MyProject` dengan nama repository yang memang ada dan bisa kamu akses.

Kalau kamu sudah punya repository lokal yang sebelumnya menggunakan HTTPS, kamu juga bisa mengubah alamat remote-nya menjadi SSH. Masuk dulu ke folder repository-nya, lalu jalankan:

```bash
git remote -v
git remote set-url origin git@github.com:USERNAME/MyProject.git
git remote -v
```

Perintah `git remote -v` pertama digunakan buat melihat alamat remote saat ini, sedangkan `git remote set-url` mengubah alamat remote `origin`. Perintah terakhir buat memastikan alamatnya sudah berubah. Perintah ini mengasumsikan repository kamu sudah punya remote bernama `origin`.

Jadi nanti ketika kamu memakai `git pull` atau `git push`, Git bisa berkomunikasi dengan GitHub melalui SSH. Gak perlu bolak-balik login ke GitHub lewat terminal. Tapi kalau kamu memasang passphrase, SSH mungkin tetap akan meminta passphrase saat key belum dimuat oleh `ssh-agent`.

### Kalau muncul error gimana?

Misalnya pas menjalankan `ssh -T git@github.com`, muncul tulisan `Permission denied (publickey)`. Biasanya ada beberapa hal yang perlu dicek: apakah public key yang benar sudah dimasukkan ke GitHub, apakah private key sudah dimuat oleh `ssh-agent`, dan apakah kamu memakai akun GitHub yang tepat.

Coba cek daftar key yang dimuat dengan `ssh-add -l`. Kalau belum ada, tambahkan lagi private key menggunakan `ssh-add` sesuai versi OS di atas. Kalau koneksi SSH berhasil tapi `git push` tetap gagal, cek juga apakah kamu benar-benar punya izin menulis ke repository tersebut.

Kalau ada peringatan fingerprint server yang gak cocok dengan informasi resmi GitHub, **jangan langsung ketik `yes`**. Periksa koneksi dan penyebabnya dulu. Kita gak mau asal mempercayai server yang salah, kan?

Buat bacaan tambahan kalau ada langkah yang terasa aneh atau error-nya belum selesai, kamu bisa cek dokumentasi resmi GitHub berikut:

- [Adding a new SSH key to your GitHub account](https://docs.github.com/en/authentication/connecting-to-github-with-ssh/adding-a-new-ssh-key-to-your-github-account)
